# 持久化不变量

一个 bbolt 文件保存 `meta/state` 和按大端 uint64 序号排序的 `items`。

- `delivered_seq <= ready_seq <= next_seq`。
- `(delivered_seq, ready_seq]` 中的消息已经发布，必须存在并可以投递。
- `(ready_seq, next_seq]` 为不可见暂存，只能在完整快照/事务结束时发布。
- `durable_lsn` 对应最后一次发布，绝不根据接收缓冲区、心跳 WAL 尾部或 JSON 长度推进。
- ACK 更新发送进度和删除对应消息处于同一事务。
- 恢复只能删除 `seq > ready_seq` 的暂存数据。

正常增量开始记录包含 wal2json 的 nextlsn，可以在收到行之前判断是否为源库重复事务。事务的 begin/commit 必须匹配，且 end LSN 一致；否则不发布、不确认。完整事务可包含多个已经分别落盘的暂存块，最后只需要原子更新元数据即可发布，不必一次性在内存重新组装事务。

初始化的生命周期为：空状态 → 持久化归属记录 → 创建 slot/取得快照 → 暂存 schema 和行 → 完整快照结束标记 → 发布为 stream。空状态遇到已存在 slot 必须拒绝接管。初始化中断仅允许删除归属明确、插件/数据库一致且未激活的本项目 slot；流式状态缺 slot 必须报错。

网络读取和反馈由一个 goroutine 拥有复制连接，避免并发读写驱动状态。HTTP 投递独立运行，只读取可见队列。容量满时采集等待接收端释放已发布数据；若只有不可见的大事务/快照占满容量则报错，避免永久等待。

PG 重启、网络失败之后会重新检查源集群、数据库、时间线、表结构和 slot。队列数据是确认源 WAL 后的唯一未投递副本，因此不能丢失或回滚本地状态。可靠性假设包括文件系统兑现同步写入，磁盘没有永久损坏，业务不绕开 slot 生命周期管理。

当前 schema 轮询只提供运行保护，不构成 DDL 日志。未来要自动同步 PG 9.4+ 的运行时 DDL，应单独设计数据库事件触发器及事务性 DDL 元数据表，并通过同一个 slot 按事务传输；不能简单“发现字段变了就查询当前 catalog”来解释历史积压 WAL。
